Inbound — email comes in

📥 Someone CCs spark.poc@gmail.com
1
Email arrives in Gmail inbox
Employee writes a thank-you, adds spark.poc@gmail.com to CC. Or forwards a customer email to it. Nothing else to do.
Sender action complete
2
Make.com polls the inbox every 5 minutes
Gmail trigger module watches for new messages. Filters out: replies from SPARK itself, auto-replies, emails from outside the team (using the roster sheet).
Make.com → Gmail connector
3
Roster lookup
Make.com looks up the sender's email in the Roster Sheet (Google Sheets tab). Gets: full name, team, manager name, manager email. This replaces Entra ID for the POC — fill it in manually once (30 min).
Google Sheets lookup

AI extraction — the brain

🧠 Claude API processes the email
4
Make.com calls Claude API (HTTP module)
Sends the email body + sender context to Claude with a structured prompt. Asks Claude to return clean JSON.
claude-haiku-4-5 · fast · cheap
5
Claude returns structured JSON
Every field needed to build the Kudos Card and store the record. If anything is unclear, Claude flags it with needs_clarification: true.
// Claude response (example) { "recipient_name": "Maria Santos", "sender_name": "James Reyes", "source_type": "peer", "what_happened": "Maria stepped in during the benefits system outage and resolved it before it impacted employees.", "core_value": "Customer-driven", "sentiment": "positive", "needs_clarification": false }
Structured JSON output
6
Make.com writes a row to Google Sheets
One row per kudos. Timestamp, sender, recipient, team, what happened, value, source type. This is the database. The Hub for POC is just this sheet, shared with the director.
Google Sheets — Kudos Log tab

Outbound — the magic moment

📤 Three emails go out automatically
7
Kudos Card → recipient's inbox
Make.com sends an HTML email from spark.poc@gmail.com to the recipient. Clean, warm, personal. The quote. Who sent it. The value it shows. This is the product.

For POC: HTML template hardcoded in Make.com email module with {{recipient_name}}, {{what_happened}}, {{core_value}} variables.
Gmail send module · HTML email
8
Manager notification → manager's inbox
Short email to the recipient's manager (looked up from the roster sheet): "Maria just received a kudos from James. Here's what they said."

Includes a mailto: button that opens a pre-filled email to Maria with a "👏 Adding my thanks — [manager name]" message already written. One click, one send.
Gmail send module · mailto: button
9
Sender confirmation → (optional, silent)
Nothing sent to the sender for POC. Keeps it clean. If they CC'd spark, they already know it worked. Add a quiet "✓ SPARK received your kudos" in v1 if people ask.
Skip for POC

Build timeline — one day

⏱ Day 1 plan
Morning · 2h
Setup
Create Gmail account. Set up Make.com. Get Claude API key from console.anthropic.com. Create the two Google Sheets tabs.
Mid-morning · 2h
Make.com scenario
Build the 9-step flow. Gmail trigger → Sheets lookup → Claude HTTP call → Sheets write → 2 email sends.
Afternoon · 2h
Email templates
Write the Kudos Card HTML. Write the manager notification. Test with a real email to spark.poc@gmail.com.
Late afternoon · 1h
Demo
Send one live kudos email in front of the director. Watch the card arrive in the recipient's inbox in under 5 minutes. That's the POC.
What the POC proves: the core loop works. Email in → AI understands → beautiful card out → manager notified. Everything else is logistics.

After the POC, migrate the same logic to M365: shared mailbox → Power Automate → Azure OpenAI → SharePoint → Outlook Adaptive Cards. The architecture is identical. Only the tools change.
