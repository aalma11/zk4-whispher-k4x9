How Power Automate talks to Claude

The actual data at every step — what gets sent, what comes back, and how it lands in SharePoint.

Step 1 — Power Automate sends the email to Claude

1
HTTP action: POST to Claude API
Power Automate → api.anthropic.com/v1/messages
What Power Automate sends (the HTTP request body)
{
  "model": "claude-haiku-4-5-20251001",
  "max_tokens": 500,
  "system": "You are SPARK, a recognition intelligence assistant.
    Extract recognition details from employee emails.
    Always return valid JSON only. No preamble.",
  "messages": [
    {
      "role": "user",
      "content": "Sender: James Reyes <james.reyes@company.com>
Subject: SPARK: Thank you Maria!
Body: Hi team, I just wanted to call out Maria Santos
from HCM Engineering. She stayed late last night to fix
the benefits system outage before it impacted employees.
Total customer-first mindset. Great job Maria!"
    }
  ]
}
The content field is built dynamically using Power Automate's dynamic content picker. You click the field, select From, Subject, and Body from the email trigger — Power Automate inserts the actual values at runtime. No coding needed.
API key: goes in the HTTP action's Headers section — not in the body. For the POC: paste it directly. For production: store in a Power Automate Environment Variable so it's not visible in the flow.

Step 2 — Claude processes and responds

2
Claude's raw API response
This is what comes back into Power Automate's HTTP action body
Claude's full response (Power Automate sees this as body('HTTP'))
{
  "id": "msg_01XFDUDYJgAACzvnptvVoYEL",
  "type": "message",
  "role": "assistant",
  "content": [
    {
      "type": "text",
      "text": "{\"recipient_name\":\"Maria Santos\",\"sender_name\":\"James Reyes\",\"source_type\":\"peer\",\"what_happened\":\"Maria stayed late to resolve a benefits system outage before it could impact employees.\",\"core_value\":\"Customer-driven\",\"sentiment\":\"positive\",\"is_recognition\":true,\"needs_clarification\":false}"
    }
  ],
  "model": "claude-haiku-4-5-20251001",
  "stop_reason": "end_turn",
  "usage": { "input_tokens": 312, "output_tokens": 89 }
}

⚠️ The one thing that trips everyone up

The JSON you care about is buried inside a string. Look at content[0].text — it's a string that contains JSON, not a JSON object. The backslashes (\") are escaped quotes inside a string.

Power Automate can't use recipient_name yet — it doesn't know it exists. You need one more step: Parse JSON. That's what cracks it open.

To get to the text string in Power Automate expressions:
body('HTTP_-_Call_Claude')?['content'][0]['text']

That's the input to your Parse JSON step.
↓

Step 3 — Parse JSON cracks it open

3
Parse JSON action
Power Automate built-in — Data Operations → Parse JSON
Input (the text string from Claude)
"{\"recipient_name\":\"Maria Santos\",
\"sender_name\":\"James Reyes\",
\"source_type\":\"peer\",
\"what_happened\":\"Maria stayed late...\",
\"core_value\":\"Customer-driven\",
\"sentiment\":\"positive\",
\"is_recognition\":true,
\"needs_clarification\":false}"
After Parse JSON — named fields you can click
{
  recipient_name  → "Maria Santos"
  sender_name     → "James Reyes"
  source_type     → "peer"
  what_happened   → "Maria stayed..."
  core_value      → "Customer-driven"
  sentiment       → "positive"
  is_recognition  → true
  needs_clarification → false
}
In the Parse JSON action, paste this as the Schema — Power Automate uses it to know what fields exist so they appear in the dynamic content picker later: 
{
  "type": "object",
  "properties": {
    "recipient_name":      { "type": "string" },
    "sender_name":         { "type": "string" },
    "source_type":         { "type": "string" },
    "what_happened":       { "type": "string" },
    "core_value":          { "type": "string" },
    "sentiment":           { "type": "string" },
    "is_recognition":      { "type": "boolean" },
    "needs_clarification": { "type": "boolean" }
  }
}
After this step, every field shows up in Power Automate's dynamic content picker — the blue pill menu where you click to insert values into other steps. No expressions needed. Just click recipient_name, what_happened, etc.
↓

Step 4 — SharePoint gets the row

4
Create item in SharePoint List
SharePoint connector → Create item — fully native, no config
SharePoint column Where the value comes from Example
Title (required by SP) ← recipient_name from Parse JSON Maria Santos
Sender ← sender_name from Parse JSON James Reyes
Source Type ← source_type from Parse JSON peer
What Happened ← what_happened from Parse JSON Maria stayed late to resolve…
Core Value ← core_value from Parse JSON Customer-driven
Team ← Team from Roster List lookup HCM Engineering
Manager Email ← Manager Email from Roster List lookup diana.cruz@co.com
Date ← Received Time from email trigger 2026-09-27
That's it. Once you configure this action — site URL, list name, and field mapping — every kudos email creates one new row automatically. No code. No database driver. No connection string. SharePoint is native to Power Automate.
↓

Step 5 — Emails go out

5
Send email (V2) — twice
Office 365 Outlook connector — same dynamic content fields
Kudos Card → recipient
To:      recipient_email (Roster lookup)
Subject: ✦ You were recognized, recipient_name!
Body:    [HTML template]
         with what_happened,
         sender_name,
         core_value
         injected as variables
Notification → manager
To:      manager_email (Roster lookup)
Subject: SPARK: recipient_name was recognized
Body:    Plain text + mailto: button
         pre-filled to recognize
         recipient_name back
The HTML Kudos Card body: in the Send Email action, click the Code View toggle (the </> button in the body field) to paste raw HTML. Power Automate will substitute the dynamic content placeholders when it sends. The recipient sees a fully rendered HTML email.

The full picture in one view

┌─────────────────────────────────────────────────────────────────┐
│                    POWER AUTOMATE FLOW                          │
└─────────────────────────────────────────────────────────────────┘

  [Trigger]  Email arrives in SPARK Inbox folder
      │
      ▼
  [Condition] Is sender = my own email? → Yes → Terminate (prevent loop)
      │ No
      ▼
  [Get items] SharePoint → SPARK Roster → filter by recipient email
      │  Returns: team, manager name, manager email
      ▼
  [HTTP]      POST api.anthropic.com/v1/messages
      │  Sends:  email from + subject + body
      │  Gets:   raw Claude response JSON
      ▼
  [Parse JSON] Input: body('HTTP')?['content'][0]['text']
      │  Unlocks: recipient_name, what_happened, core_value, etc.
      ▼
  [Condition] needs_clarification = true?
      │  → Yes → Send "who did you mean?" email to sender → Terminate
      │  → No  → continue
      ▼
  [Create item] SharePoint → SPARK Recognition list → new row
      ▼
  [Send email] Kudos Card → recipient (HTML template + dynamic values)
      ▼
  [Send email] Manager notification → manager (plain text + mailto: button)

📌
The one thing to remember: Claude's answer lives inside content[0].text as a JSON string — not a ready-made object. The Parse JSON step is what turns that string into clickable fields. Skip it and you're stuck writing raw expressions. Add it and everything becomes point-and-click.
